一、先搞清楚一件事：为什么不能 16 个一起跑

这 16 个版本原本的 docker-compose.yml 里，container_name 几乎都写死成 ysp-live（v9.4-G 起显式改为 ysp-live-v94g，v9.5-G 为 ysp-live-v95g）， 宿主端口也全部是 8767:8767。这意味着：

  • 端口冲突：宿主的 8767 只能被一个进程独占，第二个容器启动必然报 port is already allocated。
  • 容器名冲突：名字都一样，第二个直接起不来。
  • 设备身份冲突：每个版本都会向央视频注册设备身份，全跑会共用同一个家宽 IP，更容易触发频控（HTTP 400）。

所以正确姿势是 一次只跑一个，用 ysp-switch.sh 切换。订阅地址永远在 8767，播放器不用改配置。

三、快速上手

方式 A：用切换脚本（推荐，多版本通用）

在本目录打开 Git Bash（或双击 ysp-switch.bat）：

bash ysp-switch.sh list        # 看版本、本地镜像、当前运行（最新版带 ★）
bash ysp-switch.sh latest      # 切到最新版并启动（需先设 LATEST_VERSION=v9.5-G）
bash ysp-switch.sh v9.5-G      # 切到 v9.5 并启动
bash ysp-switch.sh v9.4-G      # 仍可切回上一推荐版 v9.4-G
bash ysp-switch.sh status      # 看运行状态 + 订阅地址
bash ysp-switch.sh logs        # 实时日志（Ctrl+C 退出）
bash ysp-switch.sh stop        # 停止

镜像已经构建好的话，切换只要 1 秒——脚本会自动停掉旧容器、启动新的、并探测出该版本真实可用的订阅路径。 脚本扫描到 ysp-live-docker-v9.5-G 目录，版本号记作 v9.5-G；若要让 latest 指向它，把脚本顶部 LATEST_VERSION="v9.0-G" 改成 v9.5-G 即可。

方式 B：手动 docker compose（v9.5 为例）

cd ysp-live-docker-v9.5-G      # 单层目录，compose 文件在根部
docker compose up -d --build     # 构建并启动
docker logs -f ysp-live-v95g    # 看日志（容器名已设为 ysp-live-v95g）
docker compose down             # 停止
注意目录层级不一致
  • v7.4 / v8.1 / v9.0 / v9.4-G / v9.5-G：compose 文件就在版本目录根部
  • v3.0 / v5.1 / v6.2 / v7.0 / v7.2 / v7.3：还要再进一层 ysp-live-docker/
  • v8.0：双层同名目录 ysp-live-docker-v8.0/ysp-live-docker-v8.0/（还带个 __MACOSX 垃圾目录）
  • v9.0-G：也是双层 ysp-live-docker-v9.0-G/ysp-live-docker-v9.0-G/

六、故障排查

1. 构建时报 Docker Desktop has no HTTPS proxy

根因：Docker Desktop 内置的 http.docker.internal:3128 是转发到 Windows 系统代理的。系统代理一关，拉镜像和构建全废。

# 检查（1=开，0=关）
# Windows 设置 → 网络和 Internet → 代理 → 使用代理服务器
# 或者在 FlClash / Clash Verge 里打开「系统代理」开关

开着系统代理后重试即可。注意 docker info 仍会显示 3128，别被它骗了。

2. push 报 insufficient_scope: authorization failed

根因几乎是同一个：镜像名没带用户名前缀。 docker push ysp-live:v9.5-G 会被解析成 docker.io/library/ysp-live， 而 library 是 Docker 官方保留命名空间，你永远没权限。

# 错误 ❌
docker push ysp-live:v9.5-G

# 正确 ✅
docker tag ysp-live:v9.5-G wuenci514/ysp-live:v9.5-G
docker push wuenci514/ysp-live:v9.5-G

另外确认登录状态（用凭据助手查，别看 config.json 的 auths，它在 credsStore: desktop 模式下恒为空）：

echo "https://index.docker.io/v1/" | docker-credential-desktop.exe get

密码要用 Access Token（hub.docker.com → Account Settings → Personal Access Token）， 不是账号密码。

2.5 push 卡在 Waiting，最后报 dial tcp ... connectex: A connection attempt failed

这是代理软件退出了，跟 Docker、跟账号都没关系。判断方法：

netstat -ano | findstr :7890        # 你的代理端口，看有没有 LISTENING
# 若无 LISTENING → 代理软件没开，Docker 只能直连 registry-1.docker.io，必超时

处理：重新打开 FlClash / Clash Verge 并确保「系统代理」开启，再重试。 若代理软件换过端口，也要同步改 Windows 设置里的代理服务器地址。

3. 启动报 port is already allocated

netstat -ano | findstr :8767            # 查谁占了 8767
docker stop ysp-live-v7.3               # 停掉占端口的那个

3.5 在 Docker Desktop 界面点「Run」启动的容器，浏览器连不上（ERR_CONNECTION_REFUSED）

在 Docker Desktop 镜像列表直接点 Run，容器默认只暴露端口、不做宿主机映射， 所以宿主机上 8767 没人监听，浏览器报「localhost 拒绝连接」。

# 看端口列：只显示 8767/tcp 而没有 ->8767-> 就是没映射
docker ps --format "{{.Names}}\t{{.Ports}}"

# 删掉它，改用脚本或 compose 启动
docker rm -f <容器名>
bash ysp-switch.sh v7.3

如果坚持用界面启动，必须在 Run 的可选参数里手动填 Host port = 8767 → Container port = 8767。

4. 一直显示「初始化中」或大量 HTTP 400

  • 关闭翻墙工具，或给它加分流规则，把 cctv.com、cctv.cn、yangshipin.cn 设为直连（Direct）。
  • 如果持续 400，说明你的公网 IP 被央视风控了，重启光猫换个 IP 即可恢复，不用纠结。
  • v9.5 / v9.4 / v9.0 / v9.0-G 内置设备热备池和自动轮换；v9.5 进一步修复了状态持久化与 400 自愈落盘（熔断保护：5 分钟仅换一次、每日最多 5 次），一般能自愈，可看 /diag 确认「主设备 / 热备设备」状态； /health 里的 engine.active_device_slots 就是当前可用设备槽位数。

5. 重建容器后又要重新注册设备

v7.2 及以后支持 ./data 持久化挂载，设备身份保存在版本目录的 data/ 子目录里， 各版本互相独立，重启和升级都不会丢。不要删这个目录。

七、注意事项

  • 流量：真 4K 约 15 GB/小时，1080p 约 5 GB/小时，注意宽带套餐。
  • 延迟：直播延迟约 20 秒，属正常现象。
  • 网络环境：建议家庭宽带直连运行，不要在数据中心 / 云服务器上跑。
  • 设备身份：不要同时开多个实例，容易触发央视频频控。
  • 本项目为第三方直播源代理工具，请仅用于个人学习研究，观看正式内容请通过官方渠道支持正版。
